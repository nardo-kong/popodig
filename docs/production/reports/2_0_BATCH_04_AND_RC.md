## 完成內容

- 新局使用 rules_version=2：發現、安家、加工、群體能力、深度、讀懂水線索、
  加固、舊巢、最終暖巢。目標按未滿足條件提示，教學採穩定步驟 ID。
- 6 個持久化家園里程碑；收藏展示增加家園痕跡，收藏數不是通關門檻。
- 暖巢必須已揭露、有全鼠群的乾燥安全床位、實際通路，以及附近倉儲的
  2×人口未預留食物。通關保留沙盒；舊 v6 世界保留原章節規則與可挖能力。
- v6 舊檔加上新發現資料，保留逐格已挖地形。更舊生成版本明確拒絕。
  全場景讀檔失敗會回復原狀；水／穩定度錯誤會傳回，避免部分套用壞檔。
- metrics_version=2：原料／覓食／加工產出、實際移動與負重路程、工坊工作／
  等料／滿倉、升級／收藏／風險／區域修改及家園里程碑。主時鐘排除暫停。
  1Hz 位移仍標為代理；區域修改不冒稱玩家規劃意圖。release 不建立遙測。
- 新手安全範圍 `safe_start_radius=8`，超出後保留原有風險；預設 0 保持
  舊 fixture 行為。回歸證明鄰近塌方不填回新手安全區，而遠處風險仍有效。
- 修正既有章節以 active-cell 快取非空判斷水流的問題：靜止水池仍會保留
  候選格，現在同時採用 water.is_sleeping()。
- 工坊面板可捲動、通知換行、長目標不再撐破 HUD；通關後收起教學面板。
  兩個舊 fog 單測的未釋放 Node 已補清理；壞 JSON 由回傳錯誤處理。

## 測試節奏與結果

按用戶要求，開發中只跑核心／相關增量。章節／遙測／保存／穩定度增量
274/274；批末完整單元／整合 1387/1387。修正水池條件後，最終 RC 為
**1388/1388**，包含存檔 soak，沒有腳本／解析錯誤或關閉資源錯誤。

`tools/validate_2_0.py --rc` 最終 8 階段全部通過：

1. import/parse。
2. 全套單元／整合／soak。
3. 真實自主挖掘→領獎→倉儲→JSON→防重領→壞檔回復→v6 遷移。
4. 真實採石／採礦→工坊加工→群體能力→作業中保存恢復。
5. 真實收藏→保存→C 開啟暫停／關閉恢復→視窗邊界。
6. 完整戰役，自主鼠鼠執行正常指定、設區、配方、升級、加固和撤舊倉搬遷。
7. 新進程 7 個分散種子的內容 hash 對照，0 mismatch。
8. 水系統 240 步：平均 0.615ms，p95 2.093ms，max 2.403ms，水量守恆。

本批沒有改動生成算法，因此重用第三批已執行的 **288/288 v7 種子矩陣**，
沒有重跑 288。新鮮重播再次核對其內容一致性。原始報告與重播均入庫。
最後 UI／音效清理收尾再跑相關增量（非第二次完整回歸）。
`phase20_validation.json` 記錄機器可讀結果；不是把 1.0 歷史全綠當成本輪。

## 重現入口

設定 `GODOT_BIN` 為 Godot 4.7 執行檔，執行：

```sh
python3 tools/validate_2_0.py
python3 tools/validate_2_0.py --suite=v2_progression,water_system
python3 tools/validate_2_0.py --rc
```

`--worldgen-full` 才重跑完整矩陣。RC 會建立暫時通關存檔供
`tests/phase20_layout_smoke.gd` 與 `tools/qa/benchmark_phase20_home.gd` 重用。
原生 layout／benchmark 必須移除 `--headless`；音效限制另外查 #17。
