## 2. 阶段实现史(Phase 0 → 17 + 两轮后续)

### Phase 0 — 工程地基 ✅
Godot 4.7 工程、目录架构、测试 runner、一键验证脚本、debug/release 双 profile、截图工具、冒烟测试。

### Phase 1 — 网格世界 ✅
WorldGrid/CellData/分块模型、地形渲染、相机、种子化简单世界、调试检查器、性能基线。

### Phase 2 — 挖掘与动态拓扑 ✅
左键拖画/单击指定挖掘、右键取消、合法性(前沿)判定、挖掘作业队列、鼠鼠执行挖掘、拓扑与寻路即时更新。

### Phase 3 — 鼠群模拟 ✅
饥饿/休息/危险打断三需求、作业预约系统、搬运、食物+通用材料两种资源。**备注**:原文档"初始 3 鼠"后来被 PM 指示改为 1 只(见 §3)。

### Phase 4 — 区划系统 ✅
睡眠/仓储/食物觅食三类区划、适居性判定(干湿/形状/连通)、自动布置与装饰占位、区划编辑与重划。

### Phase 5 — 结构化世界生成 ✅
八段管线:World Skeleton → Strata → Landmarks → Features → Terrain → Signal Fields → Validate → Repair。种子确定性 + 重放一致性。批量门禁:288 种子全有效、重放零失配、多样性 ≥99.65%、p95 生成 ~460ms(预算 600ms)。

### Phase 6 — 信号与根簇 ✅(一项外部门禁遗留)
根簇几何(现含 runner/forked/taproot 三种形态)、根须信号场、Signal→Reveal→Reaction→Adaptation→Stable State 五段全实现、食物产出接入。**遗留**:外部 naive 玩家"线索可读性"测试未做(Phase 12 被 PM 豁免,归并入未来外测)。

### Phase 7 — 水系统 ✅
有限水库、湿气信号、瓷砖级水流(确定性、守恒)、破口、封堵、紧急搬运、湿区状态、稳定水潭。守恒测试覆盖。

### Phase 8 — 稳定性与塌陷 ✅
弱土、逐行跨度规则(按天花板材质分档)、碎屑/裂纹/危急三段警告带、加固(消耗材料)、有界塌陷(半径 3、支撑处止住)。**注意**:PM 曾对塌陷系统的可理解性提出设计疑虑(斜挖 staircase 不塌、加固逻辑不直观),经分析后 PM 决定**暂不改动**——这是未来可复议点。

### Phase 9 — 纵向切片 UX ✅(触屏未做)
HUD、单元格检查器、上下文教程(单句推进状态机)、通知系统、30–45 分钟流程。触屏"如纳入再做"——未纳入,挂起。

### Phase 10 — 存档与加固 ✅

## 5. 当前核心缺陷(PM 体验反馈 + 最近一轮游戏性审计的合并结论)

### 5.1 PM 实玩反馈原话归纳
开局"快而不深":没有"挖开新世界"的探索感、没有"紧迫地不断解决问题"的感觉;地图缺乏引导性,玩家进来不知道下一步干嘛、解决一个问题没有成就感。

### 5.2 设计文档承诺 vs 实际体验——决策循环断点审计

GDD §4 核心循环的前两步是发动机点火器:"观察前沿信号 → 推断各段价值/风险"。决策登记册 D-002~D-007 把玩法内核定义为:**前沿是唯一决策面,选择从信息/价值/风险/成本/拓扑五梯度涌现,未知可部分推断,发现走五段式,灾难=破坏+机会**。逐环对照:

| 循环环节 | 文档要求 | 现状 | 判定 |
|---|---|---|---|
| 1 观察 | 前沿呈现多个**不同信号**的段(D-004) | 前沿是一堵均匀黑墙;信号只在已挖格旁渲染 | **断裂(主因)** |
| 2 推断 | 信号随接近可见增强:none/faint/noticeable/strong(GDD §11) | 阶梯只在模拟里,玩家读到线索时已贴脸 | **断裂** |
| 3 押注 | 五梯度可读 | 成本(硬度)✓ 拓扑✓;信息/风险两梯度不可见 | 半断 |
| 4–5 揭示 | Reveal | 模拟完整,呈现只是一行字 | 降级 |
| 6 反应 | 灾难=破坏+机会(D-007) | 首个水/塌在 38–50% 深度,第一章无实战 | **缺席** |
| 7 适应 | 多种空间响应间的选择(D-005) | 系统全在,但没有任何时刻强迫玩家选择 | 降级 |
| 8–9 稳定态/新前沿 | 稳定态成为家 | 归家感静音 | 降级 |

另有两项玩法级缺口:**前沿不平等性(D-002)从未被 worldgen 门禁验证**(batch 只验可解性/多样性);**GDD §3.5 Priority 动词缺失**(§3 表 #10)。

### 5.3 与泰拉瑞亚类游戏的根本差距(奖励经济审计)

PM 提出对照泰拉瑞亚的长时间游玩吸引力。拆解为五层机器:

1. **挖必有物**——单位挖掘时间的基础回报率(泰拉瑞亚:矿脉/洞穴/宝箱/地下小屋);
2. **看得见的承诺**——奖励获得前可见(矿在壁上发光),闪光即导航;
3. **收集图鉴元结构**——完成度驱动 + "???"条目是元承诺 + 收集物允许暂时无用;
4. **熟悉的语法 × 变化的内容**——学会识别语法,内容永远新鲜;
5. **永久性**——世界记录玩家历史。

我方现状:第 5 层有(且是愿景文档的核心回报),大发现语法(第 4 层的一半)有;但**第 1 层回报率≈0**(全世界仅 30 个特征,挖开 90% 格子一无所获)、**第 2 层为零**(无任何可见承诺)、**第 3 层为零**(无收集/图鉴/完成度)。PM 的判断"大量收集物本身即核心元素"与该审计一致。

### 5.4 缺陷定性
- 循环 1–2 环断粮是**根因**:好奇→承诺(愿景 §4 情绪弧线前两拍)没有发生条件,后续所有拍(惊讶/慌乱/掌握/归属)全部衰减;
- 第一章无危机是**内容/剧本层**(PM 判断:非根本游戏性),推迟;
- 引导缺失**应优先用世界自身的可见承诺解决**(闪光即导航),而非 UI 导航车。

## 6. 改进方向探讨(全部待 PM 决策,未实现)

### 方向一:接通决策循环(原批次 A/B,轻量)
- 迷雾半暗带(2–4 格)信号线索按距离衰减渲染——把 GDD §11 的 none/faint/noticeable 阶梯从模拟接到眼睛;已"ENCOUNTERED"类别的隐藏大特征在暗幕边缘给方向性微光。**纯呈现层、一次提交**;参数可调防剧透。
- 目标文案从"深度 18/46"改为分层勾选式;教程堆叠文本收敛。

### 方向二:构建"发现经济"(PM 认可的主菜,重做 worldgen)
按泰拉瑞亚五层补齐:
- **第 2 层·收集内容密度**:worldgen 大幅提高小发现物(闪石/罕见苔藓/化石/奇异种子/遗物/发光蘑菇等)密度,按地层带分布,validator 加密度门(每深度带 ≥N);**含前沿不平等性门禁**(补 D-002 验收)。可直接喂"每分钟回报率"。
- **第 3 层·图鉴元结构**:殖民地图鉴(按地层/类型分组,未发现显 "???" 剪影),存档持久化;可选图鉴里程碑给纯装饰奖励(喂归属感)。
- **第 4 层·语法×变化**:现有大发现加变体(不同食物/水量/遗物组合)。
- **第 5 层·永久升级收藏品(需 PM 单独拍板)**:如"古鼠遗物:鼠口上限+1"——与已锁定的人口里程碑决策冲突,故单列。
- **防失败模式**(vision §12 第一条"无脑平推"):小发现物做成看得见的精确目标(挖向它而非翻遍全部),闪光只在半暗带可见;让"看见→瞄准→挖"替代扫格。
- 代价:**worldgen v7**(288 种子基线重跑);避开锁定排除项(无合成链/科技树,收集物用途极简)。

### 方向三:剧本/内容层(承认非根本,推迟)
第一章脆弱天花板段(提前教学读警告)、小型渗水囊(签名时刻缩小版)、发现演出、里程碑祝拍、GDD §3.5 Priority 动词。**在玩法核心成立之后再排**。

### 验收方法论(两方向通用)
客观:validator/smoke 门(线索可见距离、每分钟回报率、前沿不平等性、首局节拍时序);主观:vision §11 成功标准对照实玩("是否曾在前沿停下比较两个方向?risk 是读出来的还是撞上的?"),会话遥测(预警后取消数、巢穴形态差异、发现间距)做佐证;21 §6 问卷收外测。
